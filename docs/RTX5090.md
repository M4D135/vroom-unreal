# Profils RTX 5090 — Linux et Windows

Le même projet possède un profil Mac de développement et deux profils PC destinés à une RTX 5090 : **Linux avec Vulkan SM6**, et **Windows avec DirectX 12 SM6**. Le code de conduite, les contacts, la simulation commune à 120 Hz et l'interpolation sont identiques. Les fichiers de configuration PC préparent le rendu ; ils ne constituent pas une application PC déjà compilée ou testée.

Seul le build Mac a été compilé et exécuté dans cette session. La connexion SSH configurée de david-pc a expiré pendant cette séance ; aucune inspection ni modification de son installation n’a été possible. Les dernières preuves historiques décrivent Linux et une RTX 5090, sans vérification matérielle actuelle. Le profil Windows est une option de cible ; il ne décrit pas un Windows actuellement vérifié sur david-pc.

## Configuration appliquée par plateforme

Unreal charge le socle `Config/DefaultEngine.ini`, puis les fichiers de la plateforme cible. Les réglages Mac ne limitent donc pas les builds PC.

| Fichier | Fonction |
|---|---|
| `Config/Mac/MacEngine.ini` et initialisation de `VroomGameMode` | Lumen GI High, TSR 85 %, ombres en cascades, reflets Lumen désactivés, VSync et plafond 60. |
| `Config/Linux/LinuxEngine.ini` | Vulkan SM6, support du ray tracing et Lumen matériel demandés, VSM, reflets Lumen, TSR 100 %, VSync et plafond 120. |
| `Config/Windows/WindowsEngine.ini` | DirectX 12 SM6, support du ray tracing et Lumen matériel demandés, VSM, reflets Lumen, TSR 100 %, VSync et plafond 120. |
| `Config/Linux/LinuxGameUserSettings.ini` | Valeurs initiales Linux : 3840 × 2160, plein écran fenêtré, qualité Epic et plafond 120. |
| `Config/Windows/WindowsGameUserSettings.ini` | Mêmes valeurs initiales pour Windows. |

Le ray tracing matériel est demandé avec `r.RayTracing`, `r.SkinCache.CompileShaders` et `r.Lumen.HardwareRayTracing`. Unreal n'emploie Lumen matériel que si le GPU, le pilote et le RHI le permettent ; son mécanisme de repli utilise Lumen logiciel. Aucun mode de path tracing ni réglage d'extension Vulkan non vérifié n'est forcé.

**120 images/s est un plafond, pas un résultat mesuré.** La synchronisation verticale peut limiter le débit à celui de l'écran. Le niveau Epic constitue un point de départ pour mesurer la qualité et le coût GPU sur la machine réelle ; il ne garantit pas une cadence donnée.

Les paramètres utilisateur ont le format `[/Script/Engine.GameUserSettings]`, `Version=5`, `FullscreenMode=1`. En plein écran fenêtré, Unreal utilise les dimensions du bureau. Il faut donc un bureau configuré en **3840 × 2160** pour une sortie 4K. Les anciens réglages sauvegardés dans `Saved/Config` peuvent remplacer les valeurs initiales ; vérifier les valeurs chargées avant de conclure que le profil n'a pas été appliqué.

## Préparer et lancer sous Linux

Utiliser une installation native d'Unreal Engine 5.8 pour Linux x86-64 et son environnement de compilation configuré. Depuis la racine du projet :

```sh
Tools/build_linux.sh --engine '/chemin/vers/UE_5.8'
Tools/run_linux.sh
```

Le mode par défaut prépare un package dans `Saved/Packages/Linux` en conservant les assets versionnés. Pour préparer uniquement le module Editor ou lancer ce module déjà compilé :

```sh
Tools/build_linux.sh --engine '/chemin/vers/UE_5.8' --mode editor
Tools/run_linux.sh --editor --engine '/chemin/vers/UE_5.8'
```

La génération explicite des matériaux passe par `--mode assets`. Les options `--archive`, `--width`, `--height` et `--windowed` sont décrites par `--help`. Le lancement ne recompile pas le code. Aucune de ces commandes Linux n'a été exécutée dans cette session.

## Option Windows

Utiliser Unreal Engine 5.8 pour Windows et un compilateur/SDK acceptés par cette installation. Depuis PowerShell, à la racine du projet :

```powershell
.\Tools\build_windows.ps1 -EngineRoot 'C:\Program Files\Epic Games\UE_5.8'
.\Tools\run_windows.ps1
```

Le mode par défaut prépare un package dans `Saved/Packages/Win64` en conservant les assets versionnés. `-Mode Editor` prépare le module Editor ; `-Mode Assets` régénère explicitement les matériaux. Le lancement du module Editor déjà préparé utilise :

```powershell
.\Tools\run_windows.ps1 -Editor -EngineRoot 'C:\Program Files\Epic Games\UE_5.8'
```

Les scripts acceptent notamment un chemin d'archive et une résolution explicites. Leur aide donne les paramètres complets. Aucun exécutable Windows de cette version n'a encore été compilé ou essayé ici.

## Vérifications sur la RTX 5090

Après compilation native, vérifier dans les journaux le GPU choisi, le RHI, le niveau SM6, l'activation réelle du ray tracing et les valeurs de rendu chargées. Rejouer les scénarios `slow`, `crash` et `tyre` de [COLLISIONS.md](COLLISIONS.md), puis observer les circuits, les caméras, les contacts et le HUD.

Mesurer ensuite le temps CPU et GPU en ligne droite et en virage, après préparation des shaders, à la résolution de sortie réelle. La première compilation des shaders peut allonger le démarrage. Les résultats de ce contrôle PC restent à produire ; ceux du Mac ne les remplacent pas.

**DLSS n'est pas intégré.** Les profils utilisent TSR à 100 % de l'échelle de rendu et n'ajoutent aucune génération d'images. Les voitures et décors restent les mêmes assets provisoires : une RTX 5090 et une sortie 4K ne suffisent pas à créer un rendu photoréaliste ni à prouver la fidélité au jeu original.

## Paramètres vérifiés dans le moteur local

Les noms et formats ont été contrôlés dans les sources livrées avec Unreal Engine 5.8 :

- `Core/Public/Misc/ConfigHierarchy.h` : chargement de `Config/<Plateforme>/<Plateforme><Type>.ini`.
- `Engine/Classes/Engine/RendererSettings.h` : `r.RayTracing`, `r.SkinCache.CompileShaders`, `r.Lumen.HardwareRayTracing` et `r.Shadow.Virtual.Enable`.
- `Renderer/Private/Lumen/LumenHardwareRayTracingCommon.cpp` : choix du ray tracing matériel lorsqu'il est disponible et repli logiciel.
- `Developer/Windows/WindowsTargetPlatformSettings/Classes/WindowsTargetSettings.h` et `RHI/Private/Windows/WindowsDynamicRHI.cpp` : `DefaultGraphicsRHI_DX12` et `D3D12TargetedShaderFormats`.
- `Developer/Linux/LinuxTargetPlatformSettings/Classes/LinuxTargetSettings.h` : `TargetedRHIs` et `RayTracingMode` ; `Engine/Config/VulkanPC/DataDrivenPlatformInfo.ini`, section `VULKAN_SM6`, déclare le support du ray tracing.
- `Engine/Classes/GameFramework/GameUserSettings.h` et `Engine/Private/GameUserSettings.cpp` : section de configuration, version 5, mode plein écran fenêtré 1 et résolution de bureau.

Cette vérification établit la validité des paramètres demandés, pas leur fonctionnement mesuré sur le PC inaccessible.
